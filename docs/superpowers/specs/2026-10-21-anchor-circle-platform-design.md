# 主播圈直播社交平台设计规格

## 1. 目标

在 `D:\Code\机械九院\anchor-circle-platform` 新建一套可独立部署、可产生演示数据、可完整测试的直播社交平台。产品以真实手机页面采集结果为主要依据，实现普通用户端、主播端和管理员后台；手机端优先，同时兼容桌面浏览器。

交付物必须在一台 Windows 或 Linux 机器上运行。不得依赖原站生产数据库、生产账号、生产密钥或在线服务才能完成核心演示。

## 2. 研究与复用边界

- 允许研究浏览器公开获得的页面、路由、字段、状态、接口形状和打包产物，以确认产品行为。
- 明确采用开源许可证发布的组件或项目可以按许可证复用，并在 `THIRD_PARTY_NOTICES.md` 记录来源、版本和许可证。
- 不直接复制无授权的私有源码、品牌标识、用户内容、图片视频、联系方式、支付密钥或腾讯云密钥。
- 原站只作为兼容性研究对象；交付代码必须能够独立解释、修改、测试和升级。

## 3. 已验证的真实产品能力

以下功能来自登录后的真实手机页面采集，而非教程推测。

### 3.1 登录与导航

- 账号密码登录与注册入口。
- 手机端底部导航：首页、我的。
- 未登录页面和登录失效处理。
- 手机优先布局；桌面浏览器保持可用，不显示“仅限手机访问”阻断。

### 3.2 首页与主播发现

- 直播中主播卡片、在线/热度数值、换一换。
- 每个主播展示进入圈子价格、第二视角价格及相关入口。
- 点击付费入口先展示金币解锁确认，不自动扣费。
- 主播主页包含直播、动态、圈子、素材等内容。

### 3.3 圈子与内容

- 可享权益、已加入圈子、圈子搜索、邀请码绑定。
- 圈子详情、主播相册、图片/视频分类、直播回放和权益限制。
- 创建圈子：名称、入圈金币、背景、视频、图片、说明。
- 发布普通动态：文字、缩略图/媒体、标签。
- 发布圈子动态：文字、媒体、标签、免费或收费、收费金额。
- 内容详情支持付费解锁、评论、回复、收藏和举报。
- 素材列表展示审核通过、上级审核、审核驳回和驳回原因；允许编辑被驳回素材。

### 3.4 直播与第二视角

- 主播主页选择直播场景：第二视角、直播互动。
- 直播互动配置：直播名称、描述、封面、贴图、摄像头、开始/下播、在线人数。
- 第二视角配置：邀请直播间开关、邀请码、摄像头、麦克风、网络状态、开启/下播和重连状态。
- 用户侧进入直播间、第二视角金币解锁、邀请码校验。
- 历史直播数据：日期区间、时长、音浪、订单数、订单金额。

本地默认使用 MediaMTX 和浏览器媒体能力实现可运行直播链路；提供示例视频回退模式，确保没有摄像头时仍可完成自动化验收。腾讯云直播/TRTC/TUIKit 通过适配器接入，未配置密钥时不影响本地核心功能。

### 3.5 预约、对聊与消息

- 预约状态：预支付、待聊天、聊天未完成、已结束、已失效。
- 主播对聊配置：当天/每天、开始时间、结束时间、预付比例、聊天单价、默认配置。
- 对话列表、聊天详情、未读数、文本消息。
- 视频呼叫状态：发起、同意、挂断、取消和通话记录。
- 自动化测试不向原站发送任何消息；本地环境使用种子账号完成完整交互测试。

### 3.6 账户与个人中心

- 主播中心、个人主页、金币余额和充值入口。
- 头像、昵称、简介、展示图管理。
- 收藏、设备管理、网站客服、举报反馈、添加到桌面、系统设置。
- 修改密码、退出登录。
- 账号合并、加入我们、商务合作页面。

### 3.7 会员、金币、商品与订单

- 月卡、季卡、年卡和加购会员商品。
- 会员权益：二维码权益、主播视角回放、相册/奢华内容等可配置权益。
- 固定金币套餐和自定义金额充值。
- 金币账本必须记录充值、消费、退款、赠送和管理员调整，余额由账本汇总，不允许直接无痕修改。
- 商品详情、收货地址、提交订单。
- 订单状态：未支付、待发货、待收货、已完成；支持补充地址和售后客服信息。
- 本地支付采用沙箱支付模拟器，支持成功、失败、取消、超时和退款；真实支付渠道默认关闭。

### 3.8 举报、风控与设备

- 举报投诉提交、处理中/已回复进度。
- 主播维护拉黑账号，区分同行和黑粉。
- 平台高危用户库。
- 登录/会员设备绑定和解绑。
- 风控事件、操作原因、处理人和时间必须进入审计日志。

## 4. 管理员后台补全

由于提供的账号是主播账号，以下管理功能按同类产品所需的运营闭环补全，并在界面上标记为平台管理能力。

- 仪表盘：用户、主播、直播、收入、订单、内容审核、举报、留存概览。
- RBAC：超级管理员、运营、审核员、客服、财务；菜单与操作权限分离。
- 用户与主播：查询、详情、启停用、角色、等级、会员、金币调整、设备、实名状态占位字段。
- 主播审核与资料管理：主页、素材、直播资格、权益定价、分成比例。
- 直播管理：房间状态、强制下播、回放、违规记录、第二视角和邀请码配置。
- 圈子与内容审核：动态、图片、视频、素材、评论、标签、驳回原因、批量审核。
- 商城与订单：商品、库存、地址、订单、发货、售后和退款。
- 会员与虚拟资产：套餐、权益、金币套餐、礼物、账本、音浪及兑换参数。
- 支付配置：沙箱渠道、微信/支付宝等真实渠道的配置占位、启停用、回调日志；秘密字段加密保存且不回显。
- 预约与对聊：配置、订单、通话记录、异常处理。
- 客服、举报、黑名单、高危用户、设备与风控规则。
- 字典与运营配置：标签、轮播、客服二维码、协议、上传限制、系统开关。
- 报表：用户、主播、直播、订单、金币和审核效率；支持 CSV 导出。
- 审计日志：记录管理员、动作、对象、前后值、IP、时间和结果。

## 6. 架构

采用模块化单体，避免在单机研究项目中引入不必要的微服务复杂度。

- `apps/mobile-web`：Vue 3、TypeScript、Vant、Pinia、Vue Router。
- `apps/admin-web`：Vue 3、TypeScript、Element Plus、Pinia、Vue Router。
- `apps/api`：NestJS、REST API、WebSocket、OpenAPI。
- `packages/contracts`：共享 DTO、枚举和 API 类型。
- `packages/ui-tokens`：移动端与后台共享的颜色、间距和状态规范。
- PostgreSQL：业务数据、账本、订单、审核和审计。
- Redis：会话、验证码占位、在线状态、队列和限流。
- MinIO/本地目录：图片、视频、封面和回放元数据。
- MediaMTX：本地 RTMP/WebRTC/HLS；媒体服务通过接口适配。

核心领域模块包括认证、用户、主播、直播、圈子、内容、媒体、聊天、预约、会员、钱包、支付、商品、订单、审核、举报、风控、设备、配置、报表和审计。模块之间通过公开服务接口和领域事件协作，禁止跨模块直接访问内部表。

## 7. 关键数据与一致性

- 所有主键使用 UUID；金额和金币使用整数最小单位，禁止浮点数。
- 钱包扣款、订单创建、权益发放和退款使用数据库事务与幂等键。
- 内容和素材使用草稿、待审核、通过、驳回、下架状态机。
- 直播使用准备中、直播中、重连中、已结束、异常结束状态机。
- 支付使用待支付、处理中、成功、失败、取消、超时、已退款状态机。
- 软删除仅用于需要保留审计的业务数据；审计日志不可由普通管理员删除。
- 上传校验 MIME、扩展名、大小和归属；示例环境不包含原站媒体。

## 8. 安全与隐私

- 密码使用 Argon2id；JWT 使用短期访问令牌和可撤销刷新令牌。
- 管理后台强制 RBAC、CSRF/CORS 策略、速率限制和登录失败锁定。
- 支付与云服务秘密只从环境变量或加密配置读取。
- 日志对密码、令牌、联系方式和支付字段脱敏。
- 不提供绕过审核、越权访问、抓取生产数据或复制生产用户的能力。

## 9. 部署

### 9.1 Linux

- `docker compose up -d --build` 启动 PostgreSQL、Redis、MinIO、MediaMTX、API、移动端和后台。
- 提供健康检查、数据卷、环境变量模板、备份与恢复说明。

### 9.2 Windows

- `scripts\windows\setup.ps1` 检查 Node、包管理器和 Docker 可用性。
- `scripts\windows\start-dev.ps1` 启动本地开发模式。
- `scripts\windows\start-docker.ps1` 启动与 Linux 相同的 Compose 服务。
- 提供对应 `.cmd` 包装脚本，便于双击运行。

Windows 和 Linux 使用同一套业务源码、迁移和种子数据，不维护分叉版本。

## 10. 测试与验收

- 单元测试：状态机、价格、权限、钱包、支付和校验逻辑。
- API 集成测试：每个领域的成功、失败、越权、幂等和事务回滚。
- 前端组件测试：表单校验、状态展示、权限菜单和响应式断点。
- Playwright 端到端测试：普通用户、主播、审核员和管理员完整流程。
- 本地直播冒烟测试：示例媒体推流、播放、下播和历史数据生成。
- 支付沙箱测试：成功、失败、取消、超时、重复回调和退款。
- 部署测试：Linux Compose 和 Windows PowerShell 两条启动路径。
- 种子数据必须覆盖直播中主播、普通/收费圈子、动态、审核状态、订单、预约、举报、钱包流水和报表。
- 验收输出包括测试报告、功能覆盖矩阵、已知限制和一键启动说明。

## 11. 明确限制

- 未提供腾讯云、微信或支付宝商户密钥时，相关真实外部服务只验证适配器和沙箱流程。
- 摄像头、麦克风和公网推流受浏览器权限、HTTPS 和网络环境影响；示例媒体回退保证单机验收可重复。
- “功能等价”指业务能力、流程和状态一致，不保证逐像素复制原站，也不承诺任何软件绝对零缺陷。

## 12. 完成标准

项目只有在以下条件全部满足时才算完成：

1. 移动端、管理员后台、API 和依赖服务可以在一台机器启动。
2. 四类种子账号可登录并看到正确权限。
3. 已验证功能与管理员补全功能全部进入覆盖矩阵。
4. 核心 E2E 流程产生可检查的本地数据。
5. 全量测试通过；若有环境性跳过，报告必须说明原因和人工验证方式。
6. Linux 与 Windows 部署说明经过实际命令验证。
7. README 包含架构、账号、启动、测试、备份、安全配置和外部服务接入说明。
